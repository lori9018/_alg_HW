## 2. 優化演算法的基本概念

### 2.1 什麼是優化問題？

優化（Optimization）就是在所有可能的解中，找出讓某個指標最好的那一個。一個優化問題通常包含三個要素：

| 要素 | 說明 | 在 TSP 中 |
|---|---|---|
| **決策變數 / 解** | 我們可以調整的東西 | 城市的拜訪順序 |
| **目標函數** | 衡量解好壞的數值 | 路徑總長度（越小越好） |
| **限制條件** | 解必須滿足的規則 | 每個城市恰好經過一次，且回到起點 |

所有可能解構成的集合稱為**搜尋空間（Search Space）**。

### 2.2 全域最佳解與區域最佳解

- **全域最佳解（Global Optimum）**：整個搜尋空間中最好的解。
- **區域最佳解（Local Optimum）**：比它「附近」的所有解都好，但不一定是全域最好。

可以用登山來比喻：目標函數是地形的高度，演算法是登山者。只往上走的登山者很容易停在一座小山頂（區域最佳），而看不到遠處更高的山（全域最佳）。

> 本專案求最小值，所以把「山頂」想成「谷底」即可，概念完全相同。

### 2.3 鄰域（Neighborhood）

鄰域是指「對目前的解做一個小改動，能得到哪些新解」。鄰域的設計是區域搜尋類演算法的核心：

- **交換（swap）**：交換路徑中兩個城市的位置。
- **2-opt**：拆掉兩條邊，反轉中間的一段路徑再接回去。

鄰域太小，容易卡住；鄰域太大，每一步要檢查的東西太多。

### 2.4 探索與利用（Exploration vs. Exploitation）

這是所有啟發式演算法都要面對的取捨：

- **利用（Exploitation）**：在目前找到的好解附近仔細搜尋，快速變好。
- **探索（Exploration）**：願意去看起來比較差、沒去過的地方，才有機會發現更好的區域。

偏向利用的演算法速度快但容易卡在區域最佳；偏向探索的演算法比較不容易被困住，但需要更多時間。**模擬退火**就是用溫度來調節這兩者的典型例子。

### 2.5 演算法的分類

| 分類方式 | 類型 | 說明 |
|---|---|---|
| **解的建構方式** | 建構式（constructive） | 從空的解開始，一步步加入元素（例：貪婪法） |
| | 改良式（improvement） | 從一個完整的解開始，反覆修改變好（例：2-opt、爬山、模擬退火） |
| **是否保證最佳** | 精確演算法 | 保證找到最佳解（例：窮舉、動態規劃、分支定界），但規模大時太慢 |
| | 啟發式 / 近似演算法 | 不保證最佳，但能在合理時間內給出不錯的解 |
| **是否含隨機性** | 確定性 | 同樣輸入，結果永遠相同（例：貪婪法、2-opt） |
| | 隨機性 | 過程帶有隨機，結果會變動（例：爬山、模擬退火） |

## 3. 旅行推銷員問題

**問題定義**：給定 *n* 個城市與任兩城市間的距離，求一條經過每個城市恰好一次並回到起點的最短路徑。

**為什麼困難**：*n* 個城市共有 (*n*−1)!/2 條不同的環狀路徑（不計起點與方向）。

| 城市數 n | 可能路徑數 |
|---|---|
| 10 | 約 18 萬 |
| 15 | 約 4.4 × 10¹⁰ |
| 20 | 約 6.1 × 10¹⁶ |
| 30 | 約 4.4 × 10³⁰ |

TSP 是 **NP-hard** 問題，目前沒有已知的多項式時間精確演算法。所以實務上常用啟發式演算法，在可接受的時間內取得足夠好的解。這也是本專案要比較的內容。

**本專案的距離**：使用平面上的歐式距離，並以 `tsp_data.py` 預先計算好距離矩陣 `DIST`。

## 4. 五種方法詳解

### 方法 1：改良法（2-opt）— `tsp_1_improvement_2opt.py`

**類型**：改良式、確定性

**概念**：先有一條可行路徑，再「局部修補」。2-opt 的修補動作是：選兩條邊 (a,b) 和 (c,d)，把它們換成 (a,c) 和 (b,d)，等於把 b 到 c 之間的路徑反轉。

```
原本：  ... a → b → ... → c → d ...
2-opt： ... a → c → ... → b → d ...   （b..c 這段被反轉）
```

**偽代碼**：

```
tour ← 任意初始路徑
repeat
    improved ← false
    for 每一對不相鄰的邊 (a,b), (c,d):
        if 距離(a,c) + 距離(b,d) < 距離(a,b) + 距離(c,d):
            反轉 b..c 之間的路徑
            improved ← true
until improved = false
```

**特點**：

- 每一輪掃描需要檢查 O(n²) 對邊；而且交換後只需用 O(1) 計算長度變化量 Δ，不用重算整條路徑。
- 會消除路徑中的交叉線段，這是最常見的路徑缺陷。
- 結束時得到的是「2-opt 區域最佳解」，不保證全域最佳。
- 結果取決於初始路徑，本專案用依編號排列的路徑。實務上常用貪婪法的結果當初始解，效果更好。

> **關於「改良法」這個名稱**：不同課本的說法略有差異，有時泛指「從初始解反覆改善」的所有方法。本專案選擇 2-opt 作為代表。

---

### 方法 2：爬山演算法（Hill Climbing）— `tsp_2_hill_climbing.py`

**類型**：改良式、隨機性、純區域搜尋

**概念**：像盲人爬山，每次只試探身旁一步，**更好才走，更差就不走**。

**偽代碼**：

```
tour ← 隨機路徑
repeat MAX_ITER 次:
    隨機挑兩個城市 i, j，交換位置，得到 new_tour
    if 長度(new_tour) < 長度(tour):
        tour ← new_tour          # 接受
    else:
        還原                      # 拒絕
重複整個流程 RESTARTS 次，取最短的
```

**特點**：

- 實作最簡單，是理解區域搜尋的最佳起點。
- 只接受變好的解，所以一旦陷入區域最佳就出不來。
- 補救方法是**隨機重啟（random restart）**：多次從不同起點爬山，取最好的結果。本專案重啟 10 次。
- 本實作每次嘗試都重新計算整條路徑長度（O(n)），可改成只計算變化量以加速。

---

### 方法 3：模擬退火法（Simulated Annealing, SA）— `tsp_3_simulated_annealing.py`

**類型**：改良式、隨機性、可跳出區域最佳

**概念**：來自金屬退火。金屬加熱後原子活動劇烈，慢慢冷卻才會形成穩定的低能量結構。SA 把「溫度」*T* 當作探索程度的旋鈕：

- **高溫**：很容易接受較差的解 → 大範圍探索。
- **低溫**：幾乎只接受更好的解 → 退化為爬山，精細利用。

**接受準則（Metropolis criterion）**：設新舊路徑長度差為 Δ = 新 − 舊：

```
Δ < 0（變好）  → 一定接受
Δ ≥ 0（變差）  → 以機率 exp(−Δ / T) 接受
```

Δ 越大（越差）或 T 越小，被接受的機率越低。

**偽代碼**：

```
tour ← 隨機路徑；T ← T_START
while T > T_END:
    repeat ITER_PER_T 次:
        new_tour ← 隨機 2-opt 鄰居
        Δ ← 長度(new_tour) − 長度(tour)
        if Δ < 0 或 random() < exp(−Δ/T):
            tour ← new_tour
        記錄歷史最佳
    T ← T × COOLING
回傳歷史最佳
```

**主要參數**（在檔案開頭）：

| 參數 | 預設值 | 意義 |
|---|---|---|
| `T_START` | 100 | 起始溫度，需與距離的尺度相當 |
| `T_END` | 0.001 | 結束溫度 |
| `COOLING` | 0.995 | 降溫係數，越接近 1 降得越慢、品質越好但越耗時 |
| `ITER_PER_T` | 100 | 每個溫度下嘗試的次數 |

本設定總共約 23 萬次嘗試。

**特點**：

- 理論上只要降溫夠慢，就能收斂到全域最佳解；實際上是用時間換品質。
- 對初始解不敏感。
- 需要調參，尤其是降溫速度。

### 方法 4：梯度下降法（彈性網路 Elastic Net）— `tsp_4_gradient_descent.py`

**類型**：連續優化、確定性（給定初始值）

**為什麼需要特別處理**：梯度下降要對目標函數微分，但 TSP 的解是「排列」，是離散的，沒有梯度可言。所以必須先把問題**連續化（relaxation）**。

**彈性網路的想法**（Durbin & Willshaw, 1987）：

在平面上放一個由 *M* 個節點 **y**ⱼ 組成的「彈性環」，一開始是城市中心附近的小圓。對下列能量函數做梯度下降：

```
E = −α·K · Σᵢ ln( Σⱼ exp( −‖xᵢ − yⱼ‖² / 2K² ) )   +   (β/2) · Σⱼ ‖yⱼ₊₁ − yⱼ‖²
    └──────────── 吸引項 ────────────┘               └────── 彈性項 ──────┘
```

- **吸引項**：把環上的節點往附近的城市 **x**ᵢ 拉。梯度是各城市對節點的加權吸引力，權重是 softmax。
- **彈性項**：相鄰節點之間像有彈簧，讓環保持平滑、不要拉太長。這項對應「路徑要短」。
- **K（尺度參數）**：控制吸引的範圍，起初很大（每個城市影響整個環），之後逐步縮小（每個城市只影響最近的節點）。

**每一步更新**：

```
Δyⱼ = α · Σᵢ wᵢⱼ (xᵢ − yⱼ)  +  β·K · (yⱼ₊₁ − 2yⱼ + yⱼ₋₁)
yⱼ ← yⱼ + 學習率 × Δyⱼ
```

其中 wᵢⱼ 是城市 i 對節點 j 的 softmax 權重。K 每隔 25 次迭代乘以 0.99，從 0.2 降到 0.01，總共約 7,500 次更新。

**解碼**：環最後貼合所有城市後，把每個城市對應到最近的節點，依節點在環上的順序排列，就得到 TSP 路徑。

**特點**：

- 展示了「用連續優化解離散問題」的思路，跟神經網路訓練用的梯度下降是同一個概念。
- 全程用 numpy 向量運算，不含 for 迴圈處理城市。
- 結果依賴參數（α、β、K 的衰減），而且解碼後不保證最佳。
- 若城市很密集、節點數太少，可能有兩個城市對應到同一節點，排序時以距離打破平手。

### 方法 5：貪婪演算法（最近鄰居法）— `tsp_5_greedy.py`

**類型**：建構式、確定性

**概念**：每一步都做「當下看起來最好」的選擇——走向最近的未造訪城市。

**偽代碼**：

```
tour ← [起點]
while 還有未造訪的城市:
    cur ← tour 的最後一個城市
    next ← 距離 cur 最近的未造訪城市
    把 next 加進 tour
回到起點
```

**特點**：

- 時間複雜度 O(n²)，是五種方法中最快的。
- 開頭通常很好，但越到後面剩下的城市越分散，最後常被迫走很長的「回頭路」。
- 結果只與起點有關（同一起點永遠相同）。
- 實務上常拿它的結果當作 2-opt、SA 等方法的**初始解**。
- 貪婪法不保證最佳，是因為「局部最好的選擇不一定導向全域最好」。

## 5. 實驗結果與比較

以下是預設資料（20 城市）下的一次執行結果。耗時會因機器而異，僅供參考。

| 方法 | 總長度 | 耗時 | 類型 |
|---|---|---|---|
| 1. 改良法（2-opt） | 352.331 | 約 0.1 ms | 改良式、確定性 |
| 2. 爬山演算法（10 次重啟） | 352.331 | 約 471 ms | 改良式、隨機 |
| 3. 模擬退火法 | 352.331 | 約 674 ms | 改良式、隨機 |
| 4. 梯度下降法（彈性網路） | 353.968 | 約 569 ms | 連續優化 |
| 5. 貪婪演算法 | 460.526 | 約 0.0 ms | 建構式、確定性 |

### 觀察與討論

1. **前三種方法得到相同的 352.331**，可能就是這組資料的全域最佳解。20 個城市的問題對它們來說太簡單。
2. **梯度下降法略差**（約 +0.5%）。連續化再解碼的過程會損失一些精度。
3. **貪婪法最差**（約 +31%），但速度最快。它單獨使用品質不佳，卻很適合當初始解。
4. **為什麼 2-opt 這麼快？** 在小問題上，2-opt 只需幾輪掃描就收斂；爬山與 SA 則是靠大量隨機嘗試，所以耗時較長。

### 品質與速度的取捨

```
速度快、品質低                                           速度慢、品質高
貪婪法 ──→ 2-opt ──→ 爬山（重啟）──→ 模擬退火
                         梯度下降（彈性網路）居中，且依賴參數
```

### 各方法的優缺點整理

| 方法 | 優點 | 缺點 |
|---|---|---|
| 改良法（2-opt） | 快、簡單、品質穩定 | 只能到區域最佳，依賴初始解 |
| 爬山演算法 | 最容易實作 | 容易卡住，需重啟 |
| 模擬退火 | 能跳出區域最佳，品質高 | 需調參，耗時較長 |
| 梯度下降（彈性網路） | 觀念可推廣到機器學習 | 需連續化，結果依賴參數 |
| 貪婪演算法 | 極快、完全確定 | 品質差 |

## 6. 延伸練習

1. **放大問題規模**：把 `N_CITIES` 改成 100、200，觀察五種方法的差距如何擴大。在大問題上，貪婪法與爬山法會明顯落後。
2. **組合方法**：用貪婪法的結果當 2-opt 的初始解，看是否比用依編號排列的初始解更好。
3. **調整 SA 參數**：改變 `COOLING`（例如 0.9、0.999），畫出「降溫速度 vs. 路徑品質 vs. 耗時」的關係。
4. **畫出路徑**：用 `matplotlib` 畫出城市與各方法的路徑，直觀比較（2-opt 的結果應該沒有交叉線）。
5. **多次實驗取平均**：隨機性方法每次結果不同，可換不同 `ALGO_SEED` 跑 30 次，統計平均值與標準差。
6. **加速計算**：把爬山法與 SA 改成只計算 Δ（變化量）而不是整條路徑重算，並量測加速幅度。
7. **嘗試其他方法**：遺傳演算法、蟻群演算法、Or-opt、Lin-Kernighan，以及用動態規劃（Held-Karp）求小規模的精確解來驗證最佳值。
