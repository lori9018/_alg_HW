# 作業一：求 2^n 的四種寫法與效率比較（Week 1 HW）

用四種不同寫法計算 `2**n`，再實測 `n = 100` 時的執行效率。

- 程式：[power2n.py](power2n.py)
- 執行環境：Python 3.14.7 / Windows

## 執行方式

```powershell
python power2n.py        # 預設測試 n = 100
python power2n.py 20     # 改用其他 n 值
```

程式會依序做三件事：

1. **正確性檢查**：確認四種方法在 `n = 0 ~ 10` 的結果都等於 `2 ** n`。
2. **執行效率比較**：量測各方法的函式呼叫次數與秒數。
3. **方法 2a 的指數成長實測**：證明它 `n` 每加 1 時間就翻倍，並外推 `n = 100` 的時間。

## 四種方法

| 方法 | 程式碼 | 函式呼叫次數 | 時間複雜度 |
| ---- | ------ | ------------ | ---------- |
| 方法 1　內建運算子 | `return 2 ** n` | 1 | Python 內部以快速冪實作 |
| 方法 2a　遞迴呼叫兩次 | `power2n(n-1) + power2n(n-1)` | `2^(n+1) - 1` | `O(2^n)` 指數 |
| 方法 2b　遞迴呼叫一次 | `2 * power2n(n-1)` | `n + 1` | `O(n)` 線性 |
| 方法 3　遞迴 + 查表 | 先 `if n in table` 再遞迴 | `2n + 1` | `O(n)` 線性 |

### 為什麼方法 3 比方法 2a 快？

兩份程式幾乎一模一樣，只差「**有沒有先查表**」：

```python
# 方法 2a：每次都重算 2^(n-1) 兩次
def power2n_2a(n):
    if n == 0:
        return 1
    return power2n_2a(n - 1) + power2n_2a(n - 1)   # 每一層都重做一次

# 方法 3：算過的就記在表裡，不再重算
_table = {}

def _power2n_3(n):
    if n in _table:                 # 先查表 → O(1)
        return _table[n]
    if n == 0:
        _table[0] = 1
        return 1
    result = _power2n_3(n - 1) + _power2n_3(n - 1)  # 第二次呼叫會命中表格
    _table[n] = result              # 記下來
    return result
```

方法 2a 的遞迴樹是**滿二叉樹**：節點數 `T(n) = 2·T(n-1) + 1 = 2^(n+1) - 1`。
方法 3 用表格把「算過的 n」記下來，於是每個 `n` 只真正計算一次，指數時間就降成 `O(n)`。
（這種技巧叫 **memoization 記憶化／動態規劃 DP**。）

## 實測結果：n = 100

```
方法                        函式呼叫次數          秒數   結果
-------------------------------------------------------------
方法 1  內建 2**n                   1 次    1.000e-7 s   1267650600228229401496703205376
方法 2a 遞迴呼叫兩次        2.535e+30 次（過慢，見下）   1267650600228229401496703205376
方法 2b 遞迴呼叫一次              101 次    5.000e-6 s   1267650600228229401496703205376
方法 3  遞迴 + 查表               202 次    1.430e-5 s   1267650600228229401496703205376
```

四種方法算出的結果都相同（`2^100 = 1267650600228229401496703205376`），
差別只在花的時間。

## 方法 2a 的指數成長

```
n               函式呼叫次數          秒數   成長倍數
-----------------------------------------------------
10                  2,047 次    7.860e-5 s   -
12                  8,191 次    3.121e-4 s   3.97 x
14                 32,767 次    1.253e-3 s   4.01 x
16                131,071 次    5.008e-3 s   4.00 x
18                524,287 次    2.008e-2 s   4.01 x
20              2,097,151 次    7.619e-2 s   3.79 x
```

表中每次 `n` 加 2，時間就變成約 4 倍，也就是 **`n` 每加 1，時間就乘 2**。
外推到 `n = 100`：

- 需要 `2^101 - 1 = 2,535,301,200,456,458,802,993,406,410,751` 次函式呼叫
- 估算時間約 `2.9e+15` 年 → **方法 2a 在 `n = 100` 根本不可能跑完**

所以 `run_benchmark()` 遇到呼叫次數超過 `MAX_MEASURED_CALLS`（一千萬次）時，
不會真的執行，而是用公式與實測出來的「每次呼叫耗時」外推結果。

## 結論

1. **能不用遞迴就不用**：`2 ** n` 內建運算子 0.0000001 秒就解決問題，是最快的。
2. **遞迴呼叫次數決定速度**：方法 2b 每層只呼叫一次（101 次），方法 3 雖然每層
   呼叫兩次但第二次都命中表格（202 次），兩者都是線性時間。
3. **相同的遞迴，加不加表格差 2^n 倍**：方法 2a 與方法 3 程式幾乎一樣，
   只因為少了「查表」就從天荒地老變成毫秒級。
4. **方法 3 比方法 2b 稍慢**（1.43e-5 s vs 5.0e-6 s），因為查字典比直接相乘貴；
   但兩者同樣是 `O(n)`，n 大時都很快。實務上 `2 ** n` 仍是最佳選擇。
5. **Python 的遞迴深度限制是 1000 層**，方法 2b / 方法 3 需要 `n + 1` 層，
   所以 `n` 超過約 995 會出現 `RecursionError`（方法 1、2a 則會先卡在時間上）。
