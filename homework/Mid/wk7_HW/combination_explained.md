# 組合數 C(n, k) 的計算:非動態規劃 vs 動態規劃

> 對應程式:`combination.py`

## 1. 問題定義

C(n, k) 表示從 n 個不同元素中取出 k 個(不考慮順序)的方法數:

$$C(n,k)=\frac{n!}{k!\,(n-k)!}$$

**邊界條件**

- C(n, 0) = C(n, n) = 1
- k < 0 或 k > n 時,C(n, k) = 0

**兩個重要性質**

1. **巴斯卡恆等式**:C(n, k) = C(n-1, k-1) + C(n-1, k)
   - 意義:考慮第 n 個元素,「選它」有 C(n-1, k-1) 種,「不選它」有 C(n-1, k) 種。
2. **對稱性**:C(n, k) = C(n, n-k),可用來把 k 換成較小者,減少計算量。

## 2. 非動態規劃版本

### 2.1 純遞迴(`comb_recursive`)

**原理**:直接把巴斯卡恆等式寫成遞迴。

```python
def comb_recursive(n, k):
    if k < 0 or k > n: return 0
    if k == 0 or k == n: return 1
    return comb_recursive(n-1, k-1) + comb_recursive(n-1, k)
```

**問題:重複計算**。以 C(5, 2) 為例,遞迴樹如下:

```
                    C(5,2)
                /           \
           C(4,1)             C(4,2)
          /     \            /      \
     C(3,0)   C(3,1)     C(3,1)    C(3,2)
               /  \        /  \      /   \
          C(2,0) C(2,1) C(2,0) C(2,1) C(2,1) C(2,2)
```

可以看到 C(3,1)、C(2,1) 都被重複算了好幾次,n 越大,重複情形越嚴重。

**複雜度**

| 項目 | 複雜度 | 說明 |
|---|---|---|
| 時間 | O(C(n,k)),最壞 O(2ⁿ) | 遞迴樹的葉節點全部回傳 1,所以葉節點數恰為 C(n,k),總呼叫次數為 2·C(n,k) − 1 |
| 空間 | O(n) | 遞迴深度最多為 n(呼叫堆疊) |

> 因為答案本身就是靠「一次加 1」累加出來的,所以執行時間至少和答案大小成正比,這就是它慢的根本原因。

### 2.2 公式迭代(`comb_formula`)

**原理**:把階乘約分後,只計算分子的 k 項:

$$C(n,k)=\frac{n(n-1)\cdots(n-k+1)}{k!}=\prod_{i=1}^{k}\frac{n-k+i}{i}$$

```python
k = min(k, n - k)          # 對稱性
result = 1
for i in range(1, k + 1):
    result = result * (n - k + i) // i
```

**為什麼可以用整數除法 `//`?**
第 i 步結束後,`result` 恰好等於 C(n-k+i, i),必為整數,因此每一步除法都能整除,不會產生誤差。
(注意一定要「先乘再除」,先除會得到小數或錯誤的截斷結果。)

**複雜度**

| 項目 | 複雜度 |
|---|---|
| 時間 | O(k)(取 k = min(k, n−k) 後,至多 O(n/2)) |
| 空間 | O(1) |

> 這裡的複雜度以「算術運算次數」計算。Python 整數可以任意大,當結果很大時,單次乘除的成本會隨位數增加。

## 3. 動態規劃版本

### 3.1 動態規劃的思路

動態規劃(Dynamic Programming)適用於具備以下兩個特性的問題:

1. **最佳子結構 / 遞迴關係**:大問題可由小問題的答案組成(此處就是巴斯卡恆等式)。
2. **重疊子問題**:相同的子問題會被重複用到(上面遞迴樹中重複出現的節點)。

做法是**把每個子問題的答案只算一次並存起來**,之後直接查表。

### 3.2 二維 DP(`comb_dp_2d`)

**狀態定義**:`dp[i][j]` = C(i, j)

**轉移式**:

```
dp[i][j] = 1                              if j == 0 or j == i
dp[i][j] = dp[i-1][j-1] + dp[i-1][j]      otherwise
```

**建表方式**(Bottom-up):由小到大逐列填,這就是巴斯卡三角形。

```
i\j  0   1   2   3
0    1
1    1   1
2    1   2   1
3    1   3   3   1
4    1   4   6   4
5    1   5  10  10
```

因為只需要到第 k 欄,所以表格大小是 (n+1) × (k+1)。

**複雜度**

| 項目 | 複雜度 |
|---|---|
| 時間 | O(n·k) |
| 空間 | O(n·k) |

### 3.3 一維 DP(`comb_dp_1d`,空間優化)

**觀察**:算第 i 列時,只會用到第 i−1 列,不需要保留整個表。

**做法**:用一個長度為 k+1 的陣列 `dp`,並讓 **j 由大到小** 更新:

```python
dp = [0] * (k + 1)
dp[0] = 1
for i in range(1, n + 1):
    for j in range(min(i, k), 0, -1):
        dp[j] += dp[j - 1]
```

**為什麼 j 要由大到小?**
`dp[j] += dp[j-1]` 需要用到「上一列」的 `dp[j-1]`。如果 j 由小到大,`dp[j-1]` 已經被更新成「這一列」的值,會算錯;由大到小則保證 `dp[j-1]` 還是舊值。(這和 0/1 背包的一維優化是同樣的技巧。)

**複雜度**

| 項目 | 複雜度 |
|---|---|
| 時間 | O(n·k) |
| 空間 | O(k) |

## 4. 綜合比較

### 4.1 複雜度總表

| 方法 | 類別 | 時間 | 空間 | 備註 |
|---|---|---|---|---|
| `comb_recursive` | 非 DP | O(C(n,k)) ≤ O(2ⁿ) | O(n) | 大量重複計算,只適合 n 很小 |
| `comb_formula` | 非 DP | O(k) | O(1) | 最快、最省,但只適用於「只求單一 C(n,k)」 |
| `comb_dp_2d` | DP | O(n·k) | O(n·k) | 直觀,且整張表可重複利用 |
| `comb_dp_1d` | DP | O(n·k) | O(k) | 空間優化版,只保留一列 |

### 4.2 優缺點

| 方法 | 優點 | 缺點 |
|---|---|---|
| 純遞迴 | 程式碼最短,直接對應數學定義 | 指數時間,n ≳ 30 就明顯變慢 |
| 公式迭代 | 效率最高;不需要額外記憶體 | 需注意先乘後除;偏向數學技巧,不能推廣到其他 DP 問題 |
| 二維 DP | 容易理解與除錯;一次建表可查詢所有 C(i, j)(i ≤ n, j ≤ k) | 空間用量大 |
| 一維 DP | 兼具 DP 的穩定性與較低的空間 | 只保留最後結果,無法再查詢中間的列;更新順序容易寫錯 |

### 4.3 為什麼 DP 比遞迴快?

- 純遞迴:每個 C(i, j) 可能被計算很多次,總共約 2·C(n,k) 次呼叫。
- DP:每個 C(i, j) **只計算一次**,總共 n·k 次加法。

以 C(25, 12) = 5,200,300 為例:

| 方法 | 大約運算次數 |
|---|---|
| 純遞迴 | 約 1,040 萬次函式呼叫(2 × 5,200,300 − 1) |
| DP | 約 25 × 12 = 300 次加法 |
| 公式迭代 | 12 次乘除 |

### 4.4 什麼時候用哪一種?

- **只要算一次 C(n, k)**:用公式迭代(`comb_formula`)。
- **需要大量查詢不同的 C(i, j)**(例如多筆測資、機率題、模數下的組合數):先用二維 DP 建好表,之後每次 O(1) 查表。
- **記憶體吃緊,但仍想用 DP**:用一維 DP。
- **教學 / 理解遞迴關係**:用純遞迴,再加上記憶化(見下方)。

## 5. 延伸:記憶化搜尋(Top-down DP)

在純遞迴上加入快取,就變成 Top-down 的動態規劃:

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def comb_memo(n, k):
    if k < 0 or k > n: return 0
    if k == 0 or k == n: return 1
    return comb_memo(n-1, k-1) + comb_memo(n-1, k)
```

- 時間:O(n·k)(每個狀態只算一次)
- 空間:O(n·k)(快取)+ O(n)(遞迴深度)
- 注意:n 很大時(如 n > 1000)會遇到 Python 的遞迴深度限制,此時改用 Bottom-up 較安全。

| | Top-down(記憶化) | Bottom-up(陣列填表) |
|---|---|---|
| 方向 | 從大問題往下拆 | 從小問題往上算 |
| 實作 | 遞迴 + 快取 | 迴圈 + 陣列 |
| 只計算需要的狀態 | 是 | 否(整張表都算) |
| 遞迴深度風險 | 有 | 無 |

---

## 6. 重點整理

1. 組合數的核心遞迴關係是 **C(n,k) = C(n−1,k−1) + C(n−1,k)**。
2. 純遞迴會產生大量**重疊子問題**,時間是指數級。
3. 動態規劃用**表格儲存子問題答案**,把時間降到 O(n·k)。
4. 一維 DP 利用「只依賴上一列」把空間降到 O(k),更新時必須**由大到小**。
5. 若只求單一答案,**公式迭代**(O(k) 時間、O(1) 空間)仍是最有效率的做法。
